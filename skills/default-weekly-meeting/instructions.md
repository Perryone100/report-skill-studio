# 通用周会纪要写作规则

## 目标

把录音逐字稿、智能纪要或零散工作记录整理为可供团队复盘和决策的周会纪要草稿。草稿必须保留输入中明确出现的工作项、版本、日期、完成度、负责人和风险，但不得照抄口语，也不得补造输入中没有的事实。

模型只生成符合 Schema 的结构化数据。草稿由用户确认后，应用才可以生成最终 PDF。

## 整理顺序

1. 根据已确认术语表清理明显的 ASR 错词。
2. 提取事实：已完成事项、当前状态、数字与节点、风险、下周动作、待协调事项。
3. 合并同一工作项的重复表达，并区分已经完成、正在推进和计划开展。
4. 为每个工作项建立唯一记录：名称采用逐字稿中最稳定、最具体的叫法；跨发言人的补充合并进同一行。
5. 严格按固定管理维度组织内容；项目、产品、客户、部门或负责人只是工作项属性，不是章节维度。
6. 先完成工作表，再从工作表提炼执行摘要、摘要卡片、重点项目详解、下周计划和风险，避免各处状态相互矛盾。
7. 对无法可靠判断的人名、项目名或数字写明“需进一步确认”，不要猜测。
8. 输出与 `report.schema.json` 一致的 JSON，不输出 Markdown、HTML、PDF 布局或解释文字。

## 内容结构

执行摘要位于章节之前，由 `executive_summary` 单独承载。不得再生成“本周整体结论”章节或用另一段文字重复执行摘要。

报告只包含以下四个固定章节，顺序和标题都不得改变：

1. 本周重点项目：选择本周最值得管理关注的项目，用状态卡片说明背景或目标、实质进展、当前判断以及下一节点。
2. 本周工作进展：使用一个表格汇总所有工作项，固定列为“工作项 / 本周进展 / 当前状态 / 下一步”。
3. 下周重点计划：只写输入中明确提到的计划、承诺或待办。
4. 风险与待协调事项：说明风险对象、原因、可能影响和所需协调动作；没有明确风险时写“逐字稿未提及明确风险，需人工确认”。

项目名、产品名、客户名、部门名和负责人姓名只能出现在章节内部的表格、列表或正文中，不得作为章节标题，也不得创建额外章节。一个工作项只占表格一行；同一工作项的多次发言应合并。逐字稿没有某项事实时标记“未提及”或“需确认”，不要用套话填充。

执行摘要使用 2—3 句话回答“本周处于什么阶段、取得什么实质结果、下周最值得关注什么”。摘要卡片优先使用“本周阶段 / 核心进展 / 重点风险”，只呈现可以从输入核验的短结论，不统计模型自行推断的项目数量或完成率。

“本周重点项目”不是重复工作进展表格。只选择 1—6 个符合至少一项条件的重点项目：本周形成关键交付或版本节点、临近上线或验收、存在明显风险或跨团队依赖、需要管理决策或资源协调。每个项目使用一张状态卡片：

- `title` 使用稳定、具体的项目或工作项名称；
- `status` 使用“已完成 / 进行中 / 阻塞 / 待确认”等明确判断；
- `details` 保留 2—5 条有依据的信息，优先依次说明“目标或背景 / 本周实质进展与证据 / 当前问题或判断 / 下一里程碑与动作”；
- 不逐字复制工作进展表格，不为凑数量把普通事项升级为重点项目；逐字稿没有足够依据时明确标记“需确认”。

“下周重点计划”不是把表格“下一步”逐行机械复制：应合并重复动作，保留明确承诺、时间节点、交付物和需跟进事项。风险章节同一风险只写一次；没有风险依据时不得把普通待办包装成风险。

## 表达标准

- 结论先行，语言简洁，但不能写成缺少上下文的流水账。
- 风险必须说明对象、原因和可能影响；“存在一定风险”等空泛表达不可使用。
- 待协调事项只保留可能影响交付、资源、跨团队协作、成本、质量或长期机制的内容。
- 用明确状态代替“有序推进”“持续关注”“整体良好”等无信息量表达。
- 表格的“当前状态”优先使用“已完成 / 进行中 / 阻塞 / 待确认”，不要自创模糊状态。
- “已上线”“已发布”“已交付”“已验收”不能相互替换；采用逐字稿中实际出现的完成口径。
- 有明确日期、版本号、比例或数量时原样保留；没有时间依据时不要自行补充“本周内”“月底前”等期限。
- 不在正文中展示术语表、生成方式、内容来源或内部写作口径。
- 不在页眉、页脚或副标题中添加“内容来源”“汇报口径”“输出形式”等内部制作标签。
- 业务正文可以正常描述 AI 项目、AI 生成能力、AI 生成内容及相关工作，不得因为包含“AI 生成”字样而删改真实业务信息。

## 事实边界

- 数字、日期、版本号、负责人和完成状态必须能在输入或项目记忆中找到依据。
- 不把计划写成已经完成，不把单项结果推断为整体结果。
- 输入内容相互冲突时，保留更明确或更新的说法，并标记需确认之处。
- 用户确认的纠错优先于模型判断；未确认的候选纠错不得进入长期记忆。
