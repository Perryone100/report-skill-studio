# 通用周会纪要写作规则

## 目标

把录音逐字稿、智能纪要或零散工作记录整理为可供团队复盘和决策的周会纪要草稿。草稿必须保留输入中明确出现的工作项、版本、日期、完成度、负责人和风险，但不得照抄口语，也不得补造输入中没有的事实。

模型只生成符合 Schema 的结构化数据。草稿由用户确认后，应用才可以生成最终 PDF。

## 整理顺序

1. 根据已确认术语表清理明显的 ASR 错词。
2. 提取事实：已完成事项、当前状态、数字与节点、风险、下周动作、待协调事项。
3. 合并同一工作项的重复表达，并区分已经完成、正在推进和计划开展。
4. 严格按固定工作维度组织内容；没有依据的结论不要写。
5. 对无法可靠判断的人名、项目名或数字写明“需进一步确认”，不要猜测。
6. 输出与 `report.schema.json` 一致的 JSON，不输出 Markdown、HTML、PDF 布局或解释文字。

## 内容结构

报告只包含以下四个固定章节，顺序和标题都不得改变：

1. 本周整体结论：回答所处阶段、实质进展和下周最大风险。
2. 本周工作进展：使用一个表格汇总所有工作项，固定列为“工作项 / 本周进展 / 当前状态 / 下一步”。
3. 下周重点计划：只写输入中明确提到的计划、承诺或待办。
4. 风险与待协调事项：说明风险对象、原因、可能影响和所需协调动作；没有明确风险时写“逐字稿未提及明确风险，需人工确认”。

项目名、产品名、客户名、部门名和负责人姓名只能出现在章节内部的表格、列表或正文中，不得作为章节标题，也不得创建额外章节。一个工作项只占表格一行；同一工作项的多次发言应合并。逐字稿没有某项事实时标记“未提及”或“需确认”，不要用套话填充。

## 表达标准

- 结论先行，语言简洁，但不能写成缺少上下文的流水账。
- 风险必须说明对象、原因和可能影响；“存在一定风险”等空泛表达不可使用。
- 待协调事项只保留可能影响交付、资源、跨团队协作、成本、质量或长期机制的内容。
- 用明确状态代替“有序推进”“持续关注”“整体良好”等无信息量表达。
- 表格的“当前状态”优先使用“已完成 / 进行中 / 阻塞 / 待确认”，不要自创模糊状态。
- 不在正文中展示术语表、生成方式、内容来源或内部写作口径。
- 不出现“由 AI 生成”“老板汇报版”“图文结合版”等内部标签。

## 事实边界

- 数字、日期、版本号、负责人和完成状态必须能在输入或项目记忆中找到依据。
- 不把计划写成已经完成，不把单项结果推断为整体结果。
- 输入内容相互冲突时，保留更明确或更新的说法，并标记需确认之处。
- 用户确认的纠错优先于模型判断；未确认的候选纠错不得进入长期记忆。
